# Stages 04-06: CNN input caches and the 3D and 2D CNN members

Scripts: `pipeline/04_caches.sh`, `pipeline/05_cnn3d.sh`, `pipeline/06_cnn2d.sh`,
`pipeline/smoke_cnn.sh`, plus the checkpoint replay that `pipeline/train_all.sh` runs in
`MODE=fast`. Shared conventions are described in [README.md](README.md).

## Purpose

Stage 04 builds the two crop caches the CNNs train on. Stages 05 and 06 train the three
image members that v17 ships and write the out-of-fold (OOF) files the stacker was fitted
on.

| package member | checkpoints | trainer | stacker OOF input |
|---|---|---|---|
| `mil48y` (3D hemisphere multiple-instance CNN, 48³ input) | 34 `.pt`: 5 folds each of `mil48a`, `mil48b`, `m31000`, `m33000`, `m35000`, `m37000`, and the full-data models `mf21000`, `mf23000`, `mf25000`, `mf27000` | `src/cnn3.py` | `oof_mil48y.csv`, the mean of `mil48a`, `mil48b`, `m31000` and `m33000` |
| `e2dmipf2` (2D EfficientNet-B0 on three maximum-intensity projections, 192 px) | 12 `.ts.pt`: `e2dmipf2` (seed base 9000) and `e2dmipf22` (seed base 9100), 5 folds and a full-data model each | `src/cnn2d.py`, then `tools/ts_export.py` | `oof_e2dmipf2x.csv` = 0.5 × (`e2dmipf2` + `e2dmipf22`) |
| `e2db3f2` (2D EfficientNet-B3, 224 px) | 6 `.ts.pt`: 5 folds and a full-data model | the same | `oof_e2db3f2.csv` |

The package member named `e2dmipf2` averages two training runs (tags `e2dmipf2` and
`e2dmipf22`), and its stacker weight was fitted on their two-seed mean.

On the development machine both rebuilt caches reproduced the lost originals in every
available content check, and a second rebuild gave the same bytes. A complete retrain of all
16 runs from this repository (`MODE=full`, 2026-09-28, Apple M3 Pro, MPS, torch 2.13.0) gave
all 52 checkpoints tensor-identical to the shipped and original ones, 42 of them
byte-identical, and every out-of-fold file identical. Re-exporting the original raw 2D
checkpoints to TorchScript reproduced the shipped `.ts.pt` logits exactly (max |Δlogit| = 0.0).

## Commands

From the repository root:

```bash
bash pipeline/04_caches.sh     # data/raw -> outputs/crops_v3_b.npz, outputs/crops_v3_f2.npz
bash pipeline/05_cnn3d.sh      # 10 runs -> 34 .pt, then outputs/oof_mil48y.csv
bash pipeline/06_cnn2d.sh      # backbone check, 6 runs -> 18 .pt, oof_e2dmipf2x.csv, 18 .ts.pt
bash pipeline/smoke_cnn.sh     # optional: every training command for one epoch
```

Stages 05 and 06 need `outputs/folds.csv` (stage 01) and their cache from stage 04.
Stage 06 needs network access once, to download the ImageNet weights.

Options, all passed as environment variables:

| variable | script | effect |
|---|---|---|
| `ONLY=b` or `ONLY=f2` | 04 | build one cache (default: both) |
| `FORCE=1` | 04 | rebuild a cache that already exists (default: skip it) |
| `FORCE=1` | 05, 06 | allow overwriting an existing `<tag>_fold*.pt` or `<tag>_full0.pt`. Without it the script exits 3. |
| `EPOCHS=N` | 05, 06 | epochs per run (default: the original 20 for 3D, 30 for 2D) |
| `TAG_PREFIX=p_` | 05, 06 | every tag becomes `p_<tag>`, so a rerun leaves existing checkpoints alone |
| `RUNS="..."` | 05, 06 | subset or order of runs. 05 takes family names, 06 takes `e2dmipf2 e2dmipf22 e2dmipf2:full e2dmipf22:full e2db3f2 e2db3f2:full`. |
| `EXPORT=0` | 06 | skip the TorchScript export |
| `OMP_NUM_THREADS` | 05, 06 | an exported value overrides the defaults: 2 per training run, 3 for `e2db3f2:full` and for the export |
| `ALLOW_BACKBONE_MISMATCH=1` | 06 | continue when a downloaded ImageNet weight file fails its sha256 check |
| `SMOKE_3D`, `SMOKE_2D` | `smoke_cnn.sh` | run lists of the smoke test, same syntax as `RUNS`. An empty value skips that half. |

Logs in `outputs/logs/`: `cache3_b.log` and `cache3_f2.log` (04), `<tag>.log` and
`mil48y_avg.log` (05), `fetch_backbones.log`, `<tag>.log`, `<tag>_full.log`,
`e2dmipf2x_avg.log` and `<tag>_ts_export.log` (06). With `TAG_PREFIX` the log names carry
the prefix too. The cache logs are unsafe to print in full, because a `FAIL` line, if one
occurs, names the scan's uid. `04_caches.sh` prints only the lines that start with
`[cache3]`.

### 04_caches.sh

| cache | command run by the pipeline (in `src/`) | original run |
|---|---|---|
| `crops_v3_b.npz` (3D member) | `DAT_MASK_V2=0 OMP_NUM_THREADS=2 python -u cache3.py _b` | `python cache3.py _b` on 2026-07-24, before the disc guard existed. The guard is now on by default (`preprocessing3.py` line 208), and `DAT_MASK_V2=0` selects the unguarded path the 3D member was trained on. |
| `crops_v3_f2.npz` (2D members) | `DAT_MASK_V2=1 DAT_FRAME_V2=1 OMP_NUM_THREADS=2 python -u cache3.py _f2` | the same command, run by `tools/frame_cpu_chain.sh` on 2026-09-08 |

Each cache holds the 1,362 training scans in `labels.csv` order, with the key `aligned` as
float16 of shape (1362, 48, 48, 48). `cache3.py` also writes `features_v{4,5,6}_{b,f2}.csv`
and `qc_v3_{b,f2}.csv`, which the CNNs do not read.

### 05_cnn3d.sh

Every run executes, in `src/`:

```bash
python -u cnn3.py --tag <tag> --arch mil --size 48 --key aligned --crops crops_v3_b.npz \
  --lr 1e-3 --epochs 20 --seed-base <s> [--full]
```

Fold k uses seed s + k. A `--full` model uses seed s + 99 and trains on all 1,362 rows.
The arguments come from each run's `cv_<tag>.json`. The full-data runs write no such file,
and their arguments come from the checkpoint metadata and `run_wave3.sh`.

| family | seed base | kind | original script |
|---|---|---|---|
| `mil48a` | 3000 | 5-fold | `fleet3.sh` (2026-07-24) |
| `mil48b` | 7000 | 5-fold | `fleet5.sh` (2026-07-24) |
| `mf21000`, `mf23000`, `mf25000`, `mf27000` | the number in the name | `--full` | `run_wave3.sh` (2026-07-25) |
| `m31000`, `m33000` | the number in the name | 5-fold | `run_seeds.sh` (2026-07-25) |
| `m35000`, `m37000` | the number in the name | 5-fold | `night_queue3.sh` (2026-08-22) |

After training, `cd src && python avg_member.py mil48y mil48a mil48b m31000 m33000` writes
`outputs/oof_mil48y.csv`. The script runs this step only when all four OOF files exist.
This four-run OOF is the file the v14c and v17 stacker was fitted on (coefficient 0.3718).
The shipped member averages more checkpoints: all six 5-fold runs and the four full-data
models, 34 in total, which stage 08 assembles with
`build3.py --cnn-tags mil48y=mil48a+…+mf27000 --use-full`. A six-run OOF
(`avg_member.py mil48y6 … m35000 m37000`) is informational and the stacker does not use
it.

### 06_cnn2d.sh

Step 0 runs `python tools/fetch_backbones.py`. It builds each backbone through
`cnn2d.build(..., pretrained=True)`, the trainer's own call, which downloads the weights
from the Hugging Face Hub when they are not cached. It then checks the pinned sha256 and
exits 1 on a mismatch.

Every run executes, in `src/`, `python -u cnn2d.py --tag <tag> --crops crops_v3_f2.npz
--key aligned --views mip3 --epochs 30 --lr 1e-4 --aug 1.0` with these extra arguments:

| run | extra arguments | original (script and line in the original tree) |
|---|---|---|
| `e2dmipf2` | `--res 192 --seed-base 9000` (default backbone B0) | `tools/gpu_queue2.sh:27` |
| `e2dmipf22` | `--res 192 --seed-base 9100` | `tools/f2seed2_chain.sh:6` |
| `e2dmipf2:full` | as `e2dmipf2`, plus `--full` (seed 9099) | `tools/b3_chain.sh:8` |
| `e2dmipf22:full` | as `e2dmipf22`, plus `--full` (seed 9199) | `tools/b3_chain.sh:9` |
| `e2db3f2` | `--res 224 --backbone efficientnet_b3.ra2_in1k --seed-base 9000` | `tools/post_b3_chain.sh:14` |
| `e2db3f2:full` | as `e2db3f2`, plus `--full` (seed 9099), with `OMP_NUM_THREADS=3` as in the chain | `tools/v14c_chain.sh:5` |

After training:

1. `python src/avg_2d_seeds.py e2dmipf2x e2dmipf2 e2dmipf22` writes
   `outputs/oof_e2dmipf2x.csv`: the unclipped mean 0.5 × (a + b) with the columns
   `uid,y,fold,e2dmipf2x`. This reproduces an inline pandas step of
   `tools/f2seed2_chain.sh`.
2. For each tag whose six `.pt` files exist, `python tools/ts_export.py <tag>` (run from
   the repository root) writes `<tag>_{fold0-4,full0}.ts.pt` and `<tag>_meta.json`. The
   original calls were `tools/v14b_chain.sh:6` and `tools/v14c_chain.sh:7`.

ImageNet weights, pinned by `tools/fetch_backbones.py`. Both files were downloaded on
2026-09-25 with timm 1.0.28 as `model.safetensors`. Both are Apache-2.0 and were pretrained
on ImageNet-1k, whose terms of access are non-commercial.

| Hugging Face repository | revision | bytes | sha256 |
|---|---|---:|---|
| `timm/efficientnet_b0.ra_in1k` | `1b5383e5f79cc0f7fc067e372f8f26a5fa73f26a` | 21,355,344 | `d569899762ea9b1384ee07f4af64805cf8caa1c55f9253ebb1080dc40e87a2cd` |
| `timm/efficientnet_b3.ra2_in1k` | `0366a75518620e0f2077789202073759f2d61393` | 49,335,454 | `279d2a53898aa89dab43fd6bd7df9f706aea4cb9cf916223988bbcb8e5850469` |

Both match the revisions and hashes inferred from the Hugging Face API for the files the
original run used. The original chains trained with `HF_HUB_OFFLINE=1` after caching the
weights. The pipeline leaves offline mode off, and `export HF_HUB_OFFLINE=1` is safe after
the first download. `gpu_queue2.sh` also exported `DAT_MASK_V2=1`, which has no effect on
`cnn2d.py` (it never imports `preprocessing3`), so the pipeline does not set it.

### MODE=fast: replay of the released checkpoints

`MODE=fast bash pipeline/train_all.sh` runs stage 04 and then replaces 05 and 06:

1. It copies the 30 fold checkpoints and 4 full-data checkpoints of the 3D member and the
   18 TorchScript files from `inference/assets/`, and the 18 raw 2D state dicts from
   `models/cnn_raw/` (the optional bundle `navattack_v17_cnn_raw_checkpoints.zip`, which
   already contains the `cnn_raw/` folder: `unzip navattack_v17_cnn_raw_checkpoints.zip -d
   models/`). Stage 08 needs the raw state dicts because `build3.py` reads the 2D
   architecture metadata from them. Files that already exist in `outputs/` are kept:
   `train_all.sh` copies a checkpoint only when no file of that name is there.
2. `python -u tools/replay_cnn_oof.py` (with `OMP_NUM_THREADS=3`) lets every fold checkpoint
   predict the fold it was held out from and writes `outputs/oof_<tag>.csv` in the
   trainers' format: 3D predictions clipped to [1e-6, 1 - 1e-6] without test-time
   augmentation, 2D predictions unclipped with flip augmentation. Its options are
   `--ckpt-dir DIR`, `--only 3d|2d` and `--force`.
3. `cd src && python -u avg_member.py mil48y mil48a mil48b m31000 m33000` and
   `python -u src/avg_2d_seeds.py` write the two averaged OOF files.

The replay computation is the one `tools/verify_cnn.py` checks below: on the rebuilt caches
the replayed OOF differ from the training-time OOF by at most 6.0e-7 (3D) and 1.4e-5 (2D).
In `MODE=fast`, stage 08 therefore fits the stacker on OOF files that differ from the
originals at that level.

## Verification

References: the archived per-run OOF files and QC tables in `outputs/` of the original
development tree, and the assets of the scored v17 archive. Neither original cache has a
recorded hash, because both were deleted on 2026-09-20. The rebuilt caches are therefore
checked through their content.

`tools/verify_cnn.py` holds these checks as four subcommands. It prints and stores
aggregates only, in `outputs/chk_verify_<command>.json`:

```bash
python tools/verify_cnn.py cache-b  [--assets inference/assets] [--ref-dir ORIGINAL_TREE/outputs]
python tools/verify_cnn.py cache-f2 [--assets inference/assets] [--ref-dir ORIGINAL_TREE/outputs]
python tools/verify_cnn.py spot     [--assets inference/assets] [--ref-dir ORIGINAL_TREE/outputs]
python tools/verify_cnn.py ts --pairs <tag>=<shipped_tag> ... [--out-name FILE.json]
```

`--assets` defaults to `inference/assets`. Without `--ref-dir` the comparisons with
archived files are skipped, and the normalisation check and the replayed log loss and AUROC
still run. Those can be compared with the numbers below.

### crops_v3_b.npz

The rebuild took 630 s (604 s in `cache3.py`, 3 workers, 0 failures).

  `log1p(clip(aligned, 0))`, computed as `cnn3.run_fold` computes them, equal the `mu` and
  `sd` stored in all 34 shipped checkpoints: max |Δ| = 0.0. Fold 0 gives 0.697336 and
  0.217193, the full-data models 0.698426 and 0.217027.

  runs. The original replay on the original cache had the same error profile (`mil48a`

  | `mil48b` | 0.26399 | 0.95702 |

  | `m33000` | 0.26670 | 0.95556 |

  | six-run mean | 0.26001 | 0.95848 |

  The four-run mean differs from the archived `oof_mil48y.csv` by at most 1.6e-7.
- **Side outputs.** `qc_v3_b.csv` is sha256-identical to the 2026-07-24 archive.

### Fold-0 retrains

Fold 0 of one 3D and one 2D run, retrained on the rebuilt caches with the original recipe
on MPS. `--only-fold 0` is an option of `cnn3.py` and `cnn2d.py`, which the pipeline
scripts do not expose.

- **3D.** `cd src && python -u cnn3.py --tag chk_mil48a --crops crops_v3_b.npz --lr 1e-3
  --arch mil --size 48 --key aligned --epochs 20 --seed-base 3000 --only-fold 0` trained in
  367 s and scored log loss 0.2544, AUROC 0.9576. The original log (`fleet3.log`) has
  0.2544 and 0.9576. All 38 state tensors are `torch.equal` to the shipped
  `mil48a_fold0.pt`, and `mu` and `sd` are identical. The file hashes differ
  (`12352675…` and `f44069e1…`): the current `cnn3.py` saves 15 dictionary keys where the
  2026-07-24 version saved 9 (it adds `crops`, `offset`, `crop_mm`, `out_vox`, `crops2`,
  `crops2_geom`, and the shared keys are equal), and `torch.save` names the archive folder
  after the file. Checkpoints are compared tensor by tensor for this reason. Across the six
  seeds, fold-0 log loss spans 0.2496 to 0.2702.
- **2D.** `cd src && HF_HUB_OFFLINE=1 python -u cnn2d.py --tag chk_e2dmipf2 --crops
  crops_v3_f2.npz --key aligned --views mip3 --res 192 --epochs 30 --lr 1e-4 --aug 1.0
  --seed-base 9000 --only-fold 0` trained in 337 s and scored log loss 0.2773, AUROC
  0.9516. The original fold-0 rows of `oof_e2dmipf2.csv` give 0.2773 and 0.9516 (the other
  seed, `e2dmipf22`, gives 0.2814 and 0.9538 on fold 0). All 360 state tensors and all
  metadata keys equal the original raw `e2dmipf2_fold0.pt`. Only the file hash differs,
  because of the archive folder name. Fold-0 predictions agree to max |Δp| 2.4e-7.
- **Scope.** On this machine and software stack, MPS training of the default recipe path
  of the current `cnn3.py` and `cnn2d.py` reproduced the original weights bit for bit in
  both runs, and then in the complete retrain below. On CUDA or CPU the training RNG mixes
  numpy with device-side torch draws, and results are expected within the seed spread:
  per-run OOF log loss within about 0.001 to 0.003.

### Complete retrain

`pipeline/train_all.sh` in `MODE=full` retrained all 16 runs on 2026-09-28, in a clean copy
of the released code archive with fresh environments (`docs/REPRODUCIBILITY.md`, section 5).
The checks, done with state tensors because file bytes can differ with equal weights:

- **3D.** All 34 checkpoints have 38 of 38 state tensors `torch.equal` to the shipped files,
  and equal `mu` and `sd`. The 24 checkpoints of `m31000`, `m33000`, `m35000`, `m37000` and
  the `mf*` models are byte-identical as well. The 10 of `mil48a` and `mil48b` differ in bytes
  because the current `cnn3.py` saves six metadata keys that the 2026-07-24 version did not.
- **2D.** All 18 raw state dicts are byte-identical to the original raw checkpoints (360 of
  360 tensors for B0, 574 of 574 for B3). The exported `*_meta.json` files are byte-identical.
- **Out-of-fold files.** The nine per-run files equal the archived ones (maximum absolute
  difference 0.0). `oof_mil48y.csv`, `oof_e2dmipf2x.csv` and `oof_e2db3f2.csv` are
  sha256-identical. Per-run log loss and AUROC equal the original `cv_<tag>.json` files to
  every stored digit (table in `docs/REPRODUCIBILITY.md`, section 3.2).

This is the first retrain of the `m33000`, `mf*`, `m35000`, `m37000` and `e2db3f2` families
since their original runs. It shows that the shipped `cnn3.py` reproduces all three trainer
versions on their default paths.

### TorchScript export

`tools/ts_export.py` was run on copies of the 18 original raw 2D checkpoints (tags
`chk_orig_<tag>`), taking 39 s, 38 s and 93 s on the CPU. Its eager-versus-traced checks
range from 9.1e-6 to 3.6e-5, as in the original build logs. The written `*_meta.json` files
are byte-identical to the originals. `verify_cnn.py ts` compares logits with the shipped
`.ts.pt` files on 256 images: max |Δlogit| = 0.0 for all 18 files. The file hashes differ
because a TorchScript archive records source paths (see below).

To repeat this check, copy the original raw `<tag>_{fold0-4,full0}.pt` files (the
`navattack_v17_cnn_raw_checkpoints.zip` bundle) to `outputs/chk_orig_<tag>_{...}.pt`, then
run:

```bash
python tools/ts_export.py chk_orig_<tag>
python tools/verify_cnn.py ts --assets inference/assets --pairs chk_orig_<tag>=<tag> \
  --out-name chk_verify_ts_reexport.json
```

### Smoke test

`pipeline/smoke_cnn.sh` sets `EPOCHS=1`, `TAG_PREFIX=smoke_` and `FORCE=1` and runs 3D
`mil48a` (5 folds) and `mf21000` (full data), 2D `e2dmipf2` and `e2dmipf22` (5 folds),
`e2dmipf2:full`, `e2db3f2` (5 folds) and `e2db3f2:full`, then `avg_member.py`,
`avg_2d_seeds.py` and `ts_export.py` for `smoke_e2dmipf2` and `smoke_e2db3f2`. It then
checks that every expected file exists. It passed in 641 s with 0 missing files. Per
step: 3D 5-fold 103 s, 3D full 27 s, B0 5-fold 69-70 s per seed, B0 full 21 s, B3 5-fold
174 s, B3 full 41 s, export 38 s (B0) and 92 s (B3) with eager-versus-traced differences
up to 8.2e-7, backbone check passed. The one-epoch OOF scores (log loss and AUROC:
`smoke_mil48a` 0.6800 and 0.7311, `smoke_e2dmipf2` 0.6917 and 0.6717, `smoke_e2db3f2`
0.6909 and 0.7316) only show that the code ran. An earlier smoke run without the B3
5-fold step gave identical shared metrics, so the reruns were deterministic.

## Deviations and limits

- **Thread count.** Every 3D run gets `OMP_NUM_THREADS=2`. `fleet3.sh` and `fleet5.sh`
  (`mil48a`, `mil48b`) set none. The `mil48a` fold-0 retrain and the complete retrain, both
  with 2 threads, are tensor-identical to the originals, so the setting has no effect on the
  result.
- **Working directory.** `m35000` and `m37000` originally ran as `python -u src/cnn3.py`
  from the project root. The pipeline runs every family from `src/`. `cnn3.py` resolves all
  paths from its own location, so the output is the same.
- **Trainer versions.** Three versions of `cnn3.py` trained the families: the version in the
  v3 archive (`mil48a`, `mil48b`), an unpreserved intermediate of 2026-07-25 (`m31000`,
  `m33000`, `mf*`) and the version kept as `cnn3.py.bak_v11` (`m35000`, `m37000`). The
  repository ships the final version, whose added options all default to the old
  behaviour. The complete retrain confirms this bit for bit for every family.
- **2D trainer.** The shipped `cnn2d.py` (sha256 `c08fd043…`) is the file that trained the
  2D members.
- **Readout message.** `cnn2d.py main()` tries a comparison against
  `champion_v7_CV0.2139/oof_feat3.csv` from the original tree. That file is absent, so the
  log shows `readout skipped: FileNotFoundError(...)` with a local path. The message is
  harmless, and the file was kept verbatim.
- **Overwrites.** `cnn3.py`, `cnn2d.py` and `avg_member.py` always write
  `outputs/<tag>_*.pt`, `oof_<tag>.csv` and `cv_<tag>.json`. The guard in 05 and 06 checks
  only the `.pt` files. `--only-fold` still saves `<tag>_fold<k>.pt`.
- **Prefixed exports.** With `TAG_PREFIX` the exports are named
  `<prefix><tag>_*.ts.pt` and `<prefix><tag>_meta.json`. Stage 08 expects the shipped tag
  names, so prefixed files must be renamed first.
- **Patched `tools/ts_export.py`.** Two changes, documented in its header: it traces on
  `outputs/crops_v3_f2.npz` in place of the `crops_v3_m2.npz` cache that the pipeline does
  not build (the traced graph does not depend on the sample values), and its final message
  names the file it writes (`outputs/<tag>_meta.json`).
- **New files.** `pipeline/04_caches.sh`, `05_cnn3d.sh`, `06_cnn2d.sh`, `smoke_cnn.sh`,
  `src/avg_2d_seeds.py`, `tools/fetch_backbones.py` and `tools/verify_cnn.py` did not exist
  in the original project.
- **Paths inside TorchScript files.** `torch.jit.save` stores the absolute source paths of
  the exporting machine in the `*.debug_pkl` records of each `.ts.pt`. The 18 files of the
  scored archive carry the original project path. The released weights bundle has these
  records removed, and removing them gives bit-identical outputs. A new export with
  `tools/ts_export.py` writes the local paths again.
- **Float16 caches.** Training reads float16 crops from the caches, and inference computes
  float32 crops. The original build's parity gate measured the combined effect at a mean
  of 6.6e-4 in probability.
- **Train and serve crops of the 3D member.** The 3D member was trained on unguarded crops
  (`DAT_MASK_V2=0`), and inference serves guarded crops, which differ for 29 training
  scans. This mismatch is part of the scored submission and is reproduced as is.
- **Data terms.** The two `crops_v3_*.npz` files are derived from competition data. They
  are git-ignored and must not be published.
